# 「新手小白自建 RAG」系列發布計劃

> 編輯用內部文件,不會被 Hugo 發布。
> 最後更新:2026-08-05

## 系列定位

- **敘事視角**:作者本人就是小白,第一人稱記錄「一步一步搞懂並建立 RAG」的過程。不是教學文,是探索日誌——有疑問、有查證、有踩坑。
- **核心故事線**:公司長期依賴人工處理與口述傳承,知識散落在文件與同事腦中。作者先拿自己的筆記練功建 RAG,再一步步整理公司的資料匯入儲存體,最終挑戰「把口述傳承變成問了就答的知識庫」。
- **目標讀者**:會寫一點程式、用過 ChatGPT,但沒碰過 RAG 的人;以及面臨同樣「知識都在老同事腦裡」困境的上班族工程師。
- **差異化**:(1) 小白第一人稱的真實踩坑紀錄;(2) 第二部「跟人互動、萃取口述知識」是市面 RAG 教學幾乎沒有的內容。

## 技術選型(全系列共用)

| 項目 | 選擇 | 理由 |
|------|------|------|
| 語言 | Python | 範例最多,卡關好找答案 |
| LLM / 嵌入模型 | Ollama(本地) | 免費、資料不外流、一行指令跑模型 |
| 向量資料庫 | Chroma | pip install 即用,免架伺服器 |
| 框架 | 前期不用(手刻) | 先懂原理,再決定要不要上 LangChain 等框架 |

## 發布流程

1. 文章以 `draft = true` 開發於 feature branch
2. 交叉審閱(其他模型/人工)
3. `draft = false` 後開 PR
4. **Merge 進 master 即自動發布**(Cloudflare Pages 自動建置,build command `hugo --gc --minify`,`HUGO_VERSION=0.145.0`)
